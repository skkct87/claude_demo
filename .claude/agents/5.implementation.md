### Code Organization

```
└── fixtures/
    ├── sample-marker.js
    ├── sample-config.json
    └── ... (test data)
```

### Coding Standards

1. **Naming Conventions**
   - Classes: PascalCase (`DocMetadata`, `SyncController`)
   - Functions/methods: camelCase (`extractDocBlock()`, `parseMarker()`)
   - Constants: UPPER_SNAKE_CASE (`MAX_RETRIES`, `DEFAULT_TIMEOUT`)
   - Private methods: prefix with underscore (`_validatePath()`)

2. **Error Handling**
   - Always catch and log errors
   - Provide context in error messages
   - Return consistent error format: `{ error, message, context }`
   - Never crash on component failures (graceful degradation)

3. **Logging**
   - Use logger instance: `logger.debug()`, `logger.info()`, `logger.warn()`, `logger.error()`
   - Include context: `logger.info('Parsed marker', { service, docType, file })`
   - Never log credentials or tokens

4. **Testing**
   - Minimum 80% code coverage
   - Test happy path and error cases
   - Use mocks for external dependencies (Git, File I/O)
   - Isolate tests with setup/teardown

5. **Documentation**
   - JSDoc comments for all public methods
   - Include example usage for complex functions
   - Document assumptions and limitations

## Marker Format Specification

### Marker Syntax
```javascript
/**
 * @sync
 * service=auth-service
 * docType=api
 * version=1.0.0
 * @description Login API endpoints
 */
```

### Parsed Marker Structure
```javascript
{
  service: "auth-service",
  docType: "api",
  version: "1.0.0",
  description: "Login API endpoints",
  sourceFile: "src/auth.js",
  lineNumber: 42,
  timestamp: "2024-09-25T10:30:00Z"
}
```

### Supported Doc Types
- `api` - API endpoint documentation
- `cli` - CLI command documentation
- `config` - Configuration documentation
- `schema` - Data schema documentation
- `guide` - General guide/tutorial
- `example` - Code example documentation

## Common Issues & Solutions

### Issue: Parser not finding markers
**Solution**: 
- Check marker format matches specification above
- Run parser in debug mode: `logger.level = 'debug'`
- Test with sample file in `tests/fixtures/`
- Verify file encoding (UTF-8)

### Issue: Git operations timing out
**Solution**:
- Check GitHub Actions token permissions
- Verify repository is accessible
- Increase timeout in config: `timeoutMs: 60000`
- Check network connectivity

### Issue: Conflicts in test runs
**Solution**:
- Use unique temp directories per test
- Clean up after each test
- Mock file I/O in unit tests
- Run tests serially: `jest --runInBand`

### Issue: Low test coverage
**Solution**:
- Focus on critical paths first
- Use coverage report to identify gaps
- Add tests for error scenarios
- Mock external dependencies
