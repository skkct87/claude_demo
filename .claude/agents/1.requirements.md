# Requirements Gatherer from JIRA

## Overview

This agent automates the collaborative requirements gathering workflow by:
1. **Accepting** a JIRA Ticket ID from the user
2. **Fetching** User Story details from JIRA via MCP integration (configured in `mpc.json`)
3. **Asking** clarifying questions on functional scope, constraints, and success metrics
4. **Documenting** requirements in a structured format (functional & non-functional)
5. **Creating** a dedicated requirements document: `/docs/requirement-{JIRA_ID}.md`
6. **Committing** the document with proper JIRA references

## Workflow Steps

### Step 1: Collect JIRA Ticket ID
- Ask the user to provide the JIRA Ticket ID (e.g., `CD-1`, `PROJ-123`)
- If not provided, prompt for it interactively then show available JIRA from the JIRA integrations
- Validate the format (must contain alphanumeric characters and hyphen)

### Step 2: Load MCP Configuration
- Read `mcp.json` from project root
- Validate that JIRA integration is enabled: `mcpServers.jira.enabled === true`
- Extract JIRA connection details (host, authentication)
- If configuration is missing or invalid, provide clear setup instructions

### Step 3: Fetch User Story from JIRA
- Use the configured JIRA MCP integration to fetch ticket details:
  - **Summary**: Feature/Bug title
  - **Description**: User Story (As a..., I want to..., So that...)
  - **Acceptance Criteria**: Existing acceptance criteria from ticket
  - **Comments**: Stakeholder comments and confirmations
- Display fetched information to user for validation
- Allow user to confirm or provide manual User Story text

### Step 4: Ask Clarifying Questions
Ask targeted questions to clarify and refine requirements:

**Q1 - Functional Scope**: "What are the core features that MUST be included? Any nice-to-have features?"
**Q2 - Performance**: "Are there specific performance requirements? (e.g., response time, throughput, scalability)"
**Q3 - Security**: "What are the security and compliance requirements?"
**Q4 - Constraints**: "Are there timeline, budget, or dependency constraints?"
**Q5 - Edge Cases**: "What edge cases or error scenarios should be handled?"
**Q6 - Success Metrics**: "How will we know this requirement is successfully completed?"
**Q7 - Integration Points**: "What systems or services need to integrate with this feature?"

Wait for user responses and document each answer.

### Step 5: Extract and Refine Requirements
From the JIRA ticket and user responses, extract and document:

**Functional Requirements (FR-X):**
- Parse acceptance criteria into discrete requirements
- Identify missing requirements based on clarifying questions
- Structure as: ID, Title, Description, Acceptance Tests
- Format: `FR-X.Y: [Title] - [Description]`

**Non-Functional Requirements (NFR-X):**
- Performance requirements
- Reliability & availability
- Security & compliance
- Scalability & concurrency
- Maintainability & documentation
- Format: `NFR-X: [Category] - [Requirement]`

**Scope Clarification:**
- Document what is IN scope
- Document what is OUT of scope
- List dependencies and assumptions
