## Component Responsibilities

### 1. CLI/Entry Point (`src/cli.js`)
- Parse command-line arguments (--dry-run, --services, --config)
- Initialize configuration
- Trigger SyncController
- Output final report to console

### 2. SyncController (`src/sync-controller.js`)
- Orchestrate the sync workflow
- Coordinate all components
- Handle error aggregation
- Generate final SyncReport

### 3. RepoManager (`src/repo-manager.js`)
- Clone/pull source repositories
- List files to scan
- Handle Git operations
- Support multiple service repositories

### 4. Parser (`src/parser.js`)
- Scan source files for `@sync` markers
- Validate marker format
- Extract marker metadata
- Return list of ParsedMarkers

### 5. Extractor (`src/extractor.js`)
- Process ParsedMarkers
- Extract documentation blocks
- Preserve formatting and code examples
- Build DocBlock objects with full metadata

### 6. ConflictDetector (`src/conflict-detector.js`)
- Check for duplicate doc IDs
- Compare versions
- Generate conflict warnings
- Return ConflictReport

### 7. Writer (`src/writer.js`)
- Create directory structure
- Write documentation files
- Store metadata alongside docs
- Handle file system operations
- Support dry-run mode

### 8. ReportGenerator (`src/report-generator.js`)
- Aggregate sync metrics
- Format as JSON and Markdown
- Include warnings and conflicts
- Generate summary statistics

## Data Models

### DocMetadata
```javascript
{
  id: string,              // Unique doc ID
  service: string,         // Service name
  docType: string,         // API | CLI | CONFIG | SCHEMA
  version: string,         // Semantic version
  sourceFile: string,      // Path in source repo
  lastUpdated: ISO8601,    // Timestamp
  author: string,          // Extracted from git
  tags: string[]           // Optional tags
}
```

### DocBlock
```javascript
{
  metadata: DocMetadata,
  content: string,         // Markdown content
  examples: CodeExample[], // Code examples
  relatedDocs: string[]    // Related doc IDs
}
```

### SyncReport
```javascript
{
  timestamp: ISO8601,
  dryRun: boolean,
  totalDocs: number,
  newDocs: number,
  updatedDocs: number,
  conflicts: ConflictRecord[],
  warnings: Warning[],
  executionTime: number,   // milliseconds
  failedExtractions: FailureRecord[]
}
```

## Data Flow

### Happy Path: Sync Flow

```
1. CLI receives command → SyncController.start()
2. RepoManager clones/pulls all source repos
3. RepoManager lists all files to scan
4. Parser scans files, finds @sync markers
5. Parser validates markers → ParsedMarker[]
6. Extractor processes markers → DocBlock[]
7. ConflictDetector checks for duplicates → ConflictReport
8. Writer saves docs to central repo (or previews in dry-run)
9. ReportGenerator aggregates metrics → SyncReport
10. CLI outputs report (JSON + markdown)
11. GitHub Actions commits changes (if not dry-run)
```

### Error Flow

```
- Parser encounters malformed marker
  → Log warning, add to error list, continue
- Git clone fails
  → Log error, skip service, add to failedExtractions
- File write fails
  → Add to report.failedExtractions, continue
- Conflict detected
  → Log to report.conflicts, flag for manual review
```

## Key Design Decisions

| Decision | Rationale | Alternative Considered |
|----------|-----------|------------------------|
| Modular components | Each has single responsibility, testable independently | Monolithic design |
| Config-driven services | Add new services without code changes | Hardcoded service list |
| Dry-run mode first | Validate before commit | Commit immediately |
| Structured logging | Debug and audit trail | Console.log |
| Conflict detection | Prevent data loss | Silent overwrite |
| Versioned docs | Support documentation history | Single version only |

## Non-Functional Attributes

### Scalability
- **Concurrent processing**: Services processed in parallel (Promise.all)
- **Large files**: Stream-based file reading
- **Many markers**: Batch processing in chunks

### Reliability
- **Retry logic**: Exponential backoff for API calls
- **Graceful degradation**: One service failure doesn't stop entire sync
- **Comprehensive logging**: Track all operations

### Maintainability
- **Clear module boundaries**: Dependency injection
- **Documented interfaces**: JSDoc comments
- **Configuration-driven**: Minimize code changes

### Security
- **No credential storage**: Use GitHub Actions secrets
- **Path validation**: Prevent directory traversal
- **Sanitization**: Clean extracted content
