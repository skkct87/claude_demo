# Step 7: Verification

## Objective
Generate and run a comprehensive verification suite. Verify both the code (unit + integration tests) and the final output document (content quality check).

---

## Verification Strategy

### Phase 1: Automated Testing (Continuous)
Run test suite to verify code correctness and coverage

### Phase 2: Manual Testing (Pre-Release)
Execute test scenarios to validate functionality

### Phase 3: Output Validation (Quality Check)
Verify generated documentation quality and completeness

### Phase 4: Integration Verification (End-to-End)
Test complete workflow with real repositories

---

## Phase 1: Automated Testing

### Unit Test Execution

```bash
# Run all unit tests
npm test

# Expected output:
# PASS  tests/unit/parser.test.js
# PASS  tests/unit/extractor.test.js
# PASS  tests/unit/writer.test.js
# PASS  tests/unit/conflict-detector.test.js
# PASS  tests/unit/report-generator.test.js
# ...
# Test Suites: 12 passed, 12 total
# Tests:       156 passed, 156 total
# Snapshots:   0 total
# Time:        8.234s
```

### Coverage Report

```bash
# Generate coverage report
npm test -- --coverage

# Expected minimum coverage:
# - Statements:   85%
# - Branches:     80%
# - Functions:    85%
# - Lines:        85%
```

### Linting

```bash
# Run ESLint
npm run lint

# Expected: No errors or warnings (or only info level)
```

### Verification Checklist (Phase 1)

- [ ] `npm test` passes (all tests pass)
- [ ] Coverage report shows >80% coverage
- [ ] `npm run lint` shows no errors
- [ ] No security vulnerabilities: `npm audit`
- [ ] No dependency issues: `npm list` (no conflicts)
- [ ] Build succeeds: `npm run build` (if applicable)

## Phase 2: Manual Testing

### Test Scenario 1: Happy Path (Single Service)

**Setup:**
- Create test repository with markers
- Configure config.json for single service
- Run in dry-run mode first

**Test Steps:**
```bash
# 1. Verify configuration
npm run verify-config --config config.example.json

# Expected: Configuration valid, 1 service configured

# 2. Run sync in dry-run mode
npm start --dry-run --config config.example.json

# Expected:
# - No errors
# - Finds all markers
# - Generates report
# - No files written
```

**Verification:**
- [ ] Config validation passes
- [ ] Dry-run completes without errors
- [ ] Report shows 0 conflicts
- [ ] Report shows all docs detected
- [ ] No files actually written

---

### Test Scenario 2: Multi-Service Sync

**Setup:**
- Configure 3-5 services in config.json
- Each with multiple markers
- Mix of doc types (API, CLI, config)

**Test Steps:**
```bash
# 1. Run full sync (not dry-run)
npm start --config config.json

# 2. Verify output structure
ls -R docs/
# Expected:
# docs/
# ├── service-1/
# │   ├── api/
# │   │   ├── v1.0.0/
# │   │   │   ├── doc1.md
# │   │   │   └── metadata.json
# │   └── cli/
# │       ├── v1.0.0/
# │       │   └── ...
# └── service-2/
#     └── ...
```

**Verification:**
- [ ] All services synced
- [ ] Directory structure correct
- [ ] All docs present with correct content
- [ ] Metadata files created
- [ ] No extra files created

---

### Test Scenario 3: Conflict Detection

**Setup:**
- Configure services with intentional duplicate doc IDs
- Same service/docType/version in multiple repos
- Run sync

**Test Steps:**
```bash
# 1. Run sync with known conflicts
npm start --config config-with-conflicts.json

# 2. Review report
cat report.json | grep "conflicts"

# Expected:
# - "conflicts": [
#     {"docId": "auth-service-api-1.0.0", "sources": ["repo1", "repo2"]}
#   ]
```

**Verification:**
- [ ] Conflicts detected correctly
- [ ] All conflicting docs identified
- [ ] Conflict report generated
- [ ] No auto-overwrite occurred
- [ ] Manual resolution required

---

### Test Scenario 4: Error Handling

**Setup:**
- Invalid config (missing field)
- Inaccessible repository
- Malformed markers
- Missing documentation content

**Test Steps:**
```bash
# 1. Invalid config
npm start --config invalid-config.json
# Expected: Clear error message, graceful exit

# 2. Inaccessible repo
# Configure with non-existent repo
npm start --config config-bad-repo.json
# Expected: Logs error, skips service, continues

# 3. Malformed marker
# Add marker to test file without required fields
npm start --config config.json
# Expected: Logs warning, continues with other docs

# 4. Empty content block
# Add marker with no content following
npm start --config config.json
# Expected: Logs warning, skips doc, continues
```

**Verification:**
- [ ] Invalid config caught with clear message
- [ ] Missing repos logged, sync continues
- [ ] Malformed markers logged as warnings
- [ ] Empty blocks skipped with logging
- [ ] No sync aborted due to single error

---

### Test Scenario 5: Dry-Run Mode

**Setup:**
- Use test config
- Run sync in dry-run mode
- Verify no files written

**Test Steps:**
```bash
# 1. Record file system state
ls -R docs/ > before.txt

# 2. Run dry-run
npm start --dry-run --config config.json

# 3. Check file system unchanged
ls -R docs/ > after.txt
diff before.txt after.txt

# Expected: No differences (files unchanged)
```

**Verification:**
- [ ] Dry-run mode recognized
- [ ] Report generated
- [ ] No files actually written
- [ ] Report indicates dry-run mode
- [ ] User warned before actual sync

**JSON Report Structure:**
```bash
cat sync-report.json | jq '.'

# {
#   "timestamp": "2024-09-25T10:30:00Z",
#   "dryRun": false,
#   "totalDocs": 45,
#   "newDocs": 12,
#   "updatedDocs": 33,
#   "conflicts": [],
#   "warnings": [],
#   "executionTime": 12345,
#   "failedExtractions": []
# }
```

**Verification Checklist:**
- [ ] Timestamp is valid ISO8601
- [ ] Counts are accurate (totalDocs > 0)
- [ ] Execution time reasonable (<2 min)
- [ ] No credentials in report
- [ ] All fields present and valid

### Markdown Report Quality

**Check:**
```bash
cat sync-report.md

# Verify:
# - Human-readable format
# - Clear section headers
# - Metrics table
# - Conflicts section (if any)
# - Links to synced docs (or info message)
```

**Verification Checklist:**
- [ ] Markdown syntax valid
- [ ] Headers clear and descriptive
- [ ] Metrics displayed clearly
- [ ] Conflicts listed with resolution guidance
- [ ] Warnings highlighted
- [ ] No sensitive data visible

### Documentation Quality Check

**For Each Synced Doc File:**

```bash
# Check file exists and contains content
test -f docs/auth-service/api/v1.0.0/login.md && wc -l docs/auth-service/api/v1.0.0/login.md

# Verify metadata
cat docs/auth-service/api/v1.0.0/metadata.json | jq '.service, .docType, .version'
```

**Verification Checklist:**
- [ ] All docs have content (>0 lines)
- [ ] No broken internal links
- [ ] Code examples are properly formatted
- [ ] Metadata files valid JSON
- [ ] Timestamps are recent
- [ ] Author information captured

## Phase 4: Integration Verification

### End-to-End Workflow Test

**Complete Cycle:**
```bash
# 1. Start with clean slate
rm -rf docs/
rm -rf .repo-cache/

# 2. Run full sync
npm start --config config.json

# 3. Verify all components executed
grep "Parser completed" sync.log
grep "Extractor completed" sync.log
grep "ConflictDetector completed" sync.log
grep "Writer completed" sync.log
grep "ReportGenerator completed" sync.log

# 4. Verify artifacts generated
test -f sync-report.json
test -f sync-report.md
test -d docs/
test -f docs/*/*/v*/metadata.json

# 5. Run again (verify idempotency)
npm start --config config.json

# Expected: Same results (idempotent)
```

**Verification Checklist:**
- [ ] All components execute in order
- [ ] All artifacts generated
- [ ] Report complete and accurate
- [ ] Second run produces same results (idempotent)
- [ ] Execution time consistent
